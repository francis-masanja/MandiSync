2. Client-Usage Verdict

Can demo today? YES — with caveats

Demo credentials (from data/users.json):

  • farmer@example.com
  • operator@example.com
  • admin@example.com

Password hashes are bcrypt in the JSON file; passwords are demo-grade and must be treated as public.

Demo friction (strict client will notice)

  • Middleware forces login on every path including home /
  • Home “Demo Flow” links to /demo — route does not exist (dead link)
  • Operator/admin login redirects to /dashboard and /admin — those pages do not exist
  • UI copy claims IndexedDB offline + live hardware beyond what is coded

Safe to claim

  • Interactive prototype: booking → gate verify → weighbridge → queue ledger
  • Design system + multi-role UI exploration
  • REST API sketch for integration discussions

Unsafe to claim

  • Production-ready system
  • Real hardware connectivity to cloud
  • Offline-first mobile experience
  • Password reset / OTP onboarding
  • Audited security posture

3. System / Production Verdict

productionReady: false
  • Zero automated tests + CI runs npm test with no test script → pipeline is red
  • No durable DB in the effective runtime path (see §5 DATA-01)
  • No device authentication path for ESP32 (middleware redirects API → HTML login)
  • Debug/test endpoints exposed in the production build
  • No health checks, structured logging, error boundaries, or monitoring
  • Auth store is a committed JSON file of demo users
