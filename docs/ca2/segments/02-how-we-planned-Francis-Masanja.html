How We Planned It

We planned the work in phases, used the git history to check real progress and chose a small stack that the team could finish in one semester.

Francis Masanja Hardware Integration

In one minute

First we broke the project into phases, then we kept an eye on actual progress by looking at the git history. We also picked a small tech stack that we knew the team could wrap up within a single semester.

What this part covers

We kicked off by doing requirement analysis and looking into how mandis handle arrivals today. After that we sketched out the screens, set up the database and defined the API, then moved on to building the farmer, gate, weighbridge and queue views. To keep things clean, we isolated the hardware tree, making sure the website never relies on a serial port.

We based the timeline on the actual commit dates whenever they were available. The first commit happened on 6 September 2026. The main UI and API rebuild landed on 18 September, and security and validation followed on 21 September. The final audit and bug fixes were merged on 29 October. Documentation is still in progress.

Key terms

Next.jsThe web framework that provides both the pages and the API routes.
PrismaThe database toolkit that turns the schema into typed queries.
Turso / libSQLA hosted SQLite-compatible database option.
ESP32A small Wi-Fi microcontroller used for the gate and scale nodes.

What to remember

  • We planned in phases, starting with requirements and ending with documentation.
  • The timeline uses real git commit dates, not invented ones.
  • The stack is small: one TypeScript web app, one data model and two device nodes.
  • Hardware code lives outside the website, so the site never depends on a serial port.

Baby recap

We kept the scope intentionally tiny — just a single web app, a single data model, and two device nodes. That made the semester project doable.
